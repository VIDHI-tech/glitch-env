# M3 secure media infrastructure

M3 adds Cloudflare Stream for video and Cloudflare R2 for course and student files to the PostgreSQL API. A small R2/HLS pilot adapter is also available. It does not migrate the legacy SQLite application or change curriculum content, methods, exercise policies, or existing M2 records. Migration `0012_m3-media.sql` adds media records; `0013_m3-upload-expiry.sql` records upload URL expiry; `0014_m3-video-provider.sql` backfills each existing video asset's persistent provider identity (HLS IDs start with `hls:`) and protects it on published assets. These migrations are additive.

## Trust boundaries

- The API holds Cloudflare credentials. The browser receives only a 15 minute Stream direct upload URL for an administrator, a 2 minute signed Stream playback URL for the owning student, or a 2 minute R2 presigned operation URL. Upload URLs and playback tokens are bearer credentials: do not log, cache, or share them.
- Only a super administrator or content administrator can register course media. A verified student can request a private resource upload for their own active enrollment. A student can download a course resource only when M2's existing ownership, pinned release, and unlock checks pass; a private student resource requires its owning active enrollment. Instructors receive no media management privilege by default.
- The private R2 bucket has no public binding or public ACL. R2 URLs are signed for one object and operation. Course and student keys use server generated UUIDs in separate scopes. The client never chooses a key.
- Resource upload authorization allows PDF, PNG, JPEG, WebP, UTF-8 text, and ZIP, up to 25 MiB. The signed PUT requires `If-None-Match: *`; R2 evaluates this condition atomically, so the same URL cannot overwrite the first committed staging object. Confirmation HEAD checks size and MIME and reads the first 512 bytes to check file signatures. The server copies those validated bytes into a new unguessable key, verifies the copy, then marks it ready. R2 server credentials need GetObject, PutObject, HeadObject, CopyObject, and DeleteObject permissions.
- The write-once condition is essential: a valid PUT URL remains usable until expiry, but a second PUT against its key receives a precondition failure. The exact staging object validated is therefore the object copied. This relies on Cloudflare R2's documented `PutObject` `If-None-Match` support and strong consistency; a different S3-compatible store must pass the same atomic-write regression before use.
- A release publication may pin only ready assets from that exact learning unit version. The published link and asset identity, including Stream UID, R2 key and duration, are protected by PostgreSQL triggers. A later version or media replacement requires a new release. Revocation changes availability without deleting student progress.
- A Stream webhook is accepted only when `Webhook-Signature` contains a valid HMAC SHA-256 over the timestamp and raw body within five minutes. The body digest is stored once; duplicate callbacks do not repeat effects. An old UID from a retried upload cannot update the replacement upload. Admin sync can reconcile missing callbacks. An expired pending upload renews on an idempotent upload request. Failed, expired, or processing uploads abandoned for at least one hour may be retried while their unit version remains editable and no release pins the asset; the original duration limit is preserved.
- New Stream video sessions require a ready linked asset. Playback is authorized per active enrolled student and pinned unit, then a signed token expires after two minutes. M2 watch events for Stream sessions also require an unexpired playback grant and preserve the existing session ownership, elapsed time, unique interval, and 90% plus end rules. The test-video adapter remains for M2 automated tests when no media provider is configured; production mode rejects video sessions without linked media.

## What playback evidence means

A signed playback token proves that the server authorized a request; it is not proof of viewing. M2's elapsed time and interval checks limit arbitrary completion claims, but events still originate from the client and can be fabricated by a determined authorized student. Cloudflare Stream does not provide an authenticated, per-student watch attestation in this implementation. Do not represent the completion percentage as cryptographically verified viewing. A suspended enrollment or revoked video prevents new tokens and API events immediately; a token already issued may work at Cloudflare until its two minute expiry. R2 course downloads have the same residual presigned URL window; revocation also deletes the R2 object, blocking it when deletion succeeds.

## Configuration and deployment

Set these environment variables on the **PostgreSQL API server** (plus existing `DATABASE_URL`, `BETTER_AUTH_SECRET`, and `APP_ORIGIN`). Never put them in React or commit values to Git.

| Variable | Purpose |
| --- | --- |
| `CLOUDFLARE_ACCOUNT_ID` | Enables the Cloudflare provider |
| `CLOUDFLARE_STREAM_API_TOKEN` | Stream direct upload and status API token |
| `CLOUDFLARE_STREAM_CUSTOMER_CODE` | Host for signed Stream playback URLs |
| `CLOUDFLARE_STREAM_SIGNING_KEY_ID` | Stream signing key ID |
| `CLOUDFLARE_STREAM_SIGNING_KEY_PEM_BASE64` | Base64 encoded private PEM for that key |
| `CLOUDFLARE_STREAM_WEBHOOK_SECRET` | Secret returned when configuring the Stream webhook |
| `CLOUDFLARE_R2_BUCKET` | Private R2 bucket name |
| `CLOUDFLARE_R2_ACCESS_KEY_ID` | R2 S3 token key ID |
| `CLOUDFLARE_R2_SECRET_ACCESS_KEY` | R2 S3 token secret |

1. Create a private R2 bucket with no public `r2.dev` or custom domain. Create a scoped R2 API token for that bucket. Configure browser CORS for the exact app origin and PUT headers `Content-Type` and `If-None-Match`; the browser must send `If-None-Match: *` and the signed content length. Avoid broad wildcard origins.
2. Enable Cloudflare Stream signed URLs, create a Stream signing key pair, and supply its key ID and private key. Create an API token limited to the required Stream operations. Configure direct creator uploads and set the Stream webhook endpoint to `https://<api-host>/webhooks/cloudflare/stream`; save its signing secret. Confirm Cloudflare can reach the HTTPS endpoint.
3. Back up PostgreSQL, inspect the migration journal, and apply migration `0012` before deploying the new API. Use `pnpm m1:typecheck`, `pnpm m1:build`, and `pnpm test:m3:integration` against a disposable PostgreSQL database. CI mocks Cloudflare and does not need live credentials.
4. Configure all variables in the API secret manager, deploy over HTTPS, and verify a real direct upload, processing callback, private playback, R2 upload/download, and suspension in a staging Cloudflare account. No live Cloudflare verification was performed by the automated suite.
5. Monitor provider 5xx responses, webhook 401/422 responses, processing failures, staging objects, and R2 deletion failures. Set an R2 lifecycle rule to remove stale `staging/` objects after an operationally suitable period. Retry failed Stream processing via the admin endpoint; reconcile missing callbacks with the sync endpoint.

Rollback the API deployment without reversing migration `0012`: existing M2 endpoints and data remain intact. New Stream backed releases will require the M3 API to play media, so avoid publishing them until the deployment is verified. Keep Stream videos, R2 objects, and the new tables during rollback. Do not drop `0012` while releases reference assets. No production PostgreSQL or SQLite migration was performed here.

## Known limits

The 512 byte signature check is not antivirus scanning or a full parser for PDF/ZIP. Add malware scanning and deeper format validation before accepting untrusted files in high risk environments. Cleanup of orphaned Stream uploads and failed R2 copy destinations is operational. Live Cloudflare API, webhook, CORS, conditional PUT and R2 compatibility require staging verification with actual credentials. A managed migration for existing students from legacy SQLite remains out of scope.

## Free-first R2/HLS pilot

Set `VIDEO_PROVIDER=r2-hls` to select R2/HLS for **new uploads**. Set `ENABLE_R2_HLS=1` alongside Stream as the default if both are needed. The API loads each available adapter independently, reads `media_assets.video_provider` for sync, retry, session and playback operations, and returns 503 when the asset's adapter is unavailable. A default switch never changes a pinned asset. `VideoMediaProvider` and `ObjectMediaProvider` are separate interfaces; both implementations feed the same release pinning, session, and M2 watch-event rules. Configure Stream credentials as well when existing releases reference Stream, even if new uploads default to HLS.

| Choice | Pilot cost model | Engineering and delivery trade-off |
| --- | --- | --- |
| Cloudflare Stream | [Stored minutes and delivered minutes](https://developers.cloudflare.com/stream/pricing/) are billed; currently $5 per 1,000 stored minutes/month and $1 per 1,000 delivered minutes. | Managed transcoding, adaptive playback, and CDN delivery. Signed URLs have a residual access window after revocation. |
| Private R2 + FFmpeg + API HLS proxy | [R2 Standard](https://developers.cloudflare.com/r2/pricing/) includes 10 GB-month, 1 million Class A and 10 million Class B operations in its free tier, with no R2 egress charge. Encoding CPU, API bandwidth, database checks, and hosting are additional costs. | Cheap at tiny scale but every manifest and segment crosses the API. One 480p rendition, no adaptive bitrate, CDN edge caching, captions, thumbnailing, or high-concurrency guarantee. |

The worker polls pending MP4 uploads, validates expected size and MIME, probes duration, encodes H.264/AAC with FFmpeg into four-second MPEG-TS segments, then writes segments, manifest and a final metadata marker to a **private** R2 bucket. The API accepts a 1–800 second HLS duration limit and a source up to 100 MiB; the worker also enforces 200 segments and 8 MiB per segment. An actual source longer than its declared limit fails processing. A ready database state is set only after the final marker exists. Worker failures become `failed`; an admin can use `/retry` for editable, unpinned assets. A killed worker leaves a processing row; the worker requeues it after 15 minutes on restart, longer than its ten-minute FFmpeg timeout. Duplicate workers claim jobs with row locking, then release the lock before encoding. Expired pending uploads renew with a new UID. Old source and partial-output keys with no matching asset are deleted after one hour; an R2 lifecycle rule remains advisable for infrastructure outages. This is a pilot bound, not a general video service.

The API returns a same-origin manifest path after a ten-minute playback grant. Each manifest and segment GET checks the authenticated student, active enrollment, pinned unlocked unit, ready asset, live session and grant expiry, then fetches the allowlisted object from private R2. It commits the authorization transaction before transferring bytes and rechecks enrollment, asset and grant immediately afterward, so a suspension during the R2 read is denied. A suspension after the final check can still race an in-flight response. Responses use `private, no-store`. Every segment costs two database checks and one R2 GET; there is no CDN cache or adaptive bitrate. Pilot capacity is bounded by API connections, database capacity, R2 request latency and one FFmpeg worker per active encode. The browser must use credentialed same-origin HLS playback. As with Stream, an authorized client can fabricate watch events within M2's timing rules; HLS transport does not attest attention.

### Local Compose environment

Run `docker compose -f compose.media-dev.yml up --build` from the repository root. It starts PostgreSQL 17, private MinIO as an R2-compatible **local test store**, a one-shot bucket initializer, the Fastify API at `http://127.0.0.1:3002`, and one FFmpeg worker. The local-only MinIO binary is built from the pinned upstream `RELEASE.2025-10-15T17-29-55Z` source because public prebuilt images were unavailable; it is not a production storage deployment. PostgreSQL and MinIO are persisted in named volumes. PostgreSQL and MinIO bind only to host loopback (`55433`, `9000`, `9001`); the hard-coded credentials and mail-capture flag are development-only. The API runs the additive migrations on startup. For captured verification email, use `docker compose -f compose.media-dev.yml exec api node -e "fetch('http://127.0.0.1:3002/__dev/mail').then(r=>r.json()).then(console.log)"` from the local machine. Browser uploads to MinIO need bucket CORS permitting the exact local origin and signed `Content-Type`, `Content-Length`, and `If-None-Match` request headers. CI's separate container job uses two workers and real MP4 bytes.

Across two GitHub runner runs, ten sequential reads of one five-second video's segment took 6.5–29.1 ms each; batches of ten concurrent reads completed in 63.7–100.8 ms. These measurements include the loopback API, PostgreSQL and MinIO in one runner. They do not measure internet latency, real R2, sustained concurrency, or larger assets. A pilot should load-test its own API and database before choosing a user limit; no production capacity is claimed.

For real R2, set `CLOUDFLARE_R2_BUCKET`, `CLOUDFLARE_R2_ACCESS_KEY_ID`, `CLOUDFLARE_R2_SECRET_ACCESS_KEY`, and `CLOUDFLARE_ACCOUNT_ID`. Leave `R2_ENDPOINT` and `R2_PUBLIC_ENDPOINT` unset; those are only for the local S3-compatible endpoint. Keep the bucket private, create lifecycle cleanup rules for abandoned `hls/source/`, partial `hls/output/` and `staging/` objects, and provision CPU/disk space for the worker's temporary files. Verify conditional PUT, browser CORS, upload, encoding, playback, suspension and retry with the target provider before pilot use. The R2/HLS pilot has no live Cloudflare verification in CI.

Rollback by reverting the API and worker while retaining migrations and R2 objects. Stop publishing new HLS releases first; existing HLS-backed releases require the HLS routes to play. Preserve PostgreSQL and media volumes during local rollback. No production or legacy SQLite data migration was performed.
